三、实现决策与踩坑记录（改代码前先看这里）

决策 / 坑说明
stdout 归协议 MCP stdio 传输用 stdout 收发 JSON-RPC 帧。SDK 自带 fd 级隔离（服务启动后 fd 1 被改道到 stderr，协议走私有副本），不需要自己做 stdout 重定向；但自己加的日志一律走 stderr。
anyio vendor 兜底 venv 里 mcp 2.3.0 能 import 但 anyio 半残。mcp_server.py 启动时把 vendor/ 插到 sys.path 最前兜底，这也是 core 各模块的同款做法。
scan 会设激活库 扫描工具沿用 Web 端行为，会把被扫库设为激活库。e2e 测试曾把激活库翻成 _testlib，测完需 HUB.set_active() 还原。
fmt_ts 不是 Store 方法 fmt_ts 是 core/store.py 的模块级函数。st.fmt_ts() 会 AttributeError——app.py 的 /api/lines 曾因此 500（已修），新代码一律 from core import store as store_mod 后 store_mod.fmt_ts()。
DynamicVRAM 必须复刻 服务端 main.py 在 import torch 前 aimdo.control.init()，加载模型前 init_devices() 并把 CoreModelPatcher 换成 ModelPatcherDynamic。直调跳过这一步 → VAE/CLIP 落静态 ModelPatcher，comfy.ops 逐 op 搬运覆盖不到 ViT3DDecoder.register_tokens（裸 torch.cat），VAE 解码必崩 "tensors is on cpu vs cuda:0"。h3gen.py 1b 节复刻；探针 _vae_probe.py 可单独验证。
cudaMallocAsync 必须复刻 服务端 import torch 前 import cuda_malloc（torch 2.x+CUDA+卡不在黑名单 → 自动设 PYTORCH_CUDA_ALLOC_CONF=backend:cudaMallocAsync）。缺这一步：流式加载 + VAE 解码大块激活把原生分配器打碎，reserved 几个 G 却连 30MB 都分不出 → OOM。环境变量必须在 import torch 之前设。
SaveVideo 的 codec 传字符串 V3 DynamicCombo 的 API 值是选项键字符串（"codec": "auto"），后端 build_nested_inputs 按 codec.codec 嵌套路径自动包成 execute 要的 dict。传 {"codec":"auto"} 反而匹配不上选项、codec 整个丢失，报 missing 1 required positional argument。直调版已绕开这条——h3gen 用 ffmpeg 直接合成 mp4。
模板直调三处改名 照 UI 工作流手抄 API 格式会踩：BasicScheduler 新版要接 model；SamplerCustomAdvanced 的 latent 改名 latent_image；ComfyMathExpression 是 V3 autogrow 输入，改成 Python 直算帧数（5+17k）更稳。
netstat 按字节读 中文 Windows 的 netstat 输出是 GBK，subprocess text=True 按 UTF-8 解会 UnicodeDecodeError。server_pid() 用 decode("utf-8","replace")。
root 回传 line_id 只在各自库内唯一。多库场景搜索结果里的 root 必须带给后续工具；省略时按 env FRAMESEEK_ROOT → 激活库解析。
导入要轻 core/verify、boxaudit、store、hub 导入即轻量；ocr 重依赖在工具首次调用时才加载；asr.device_info() 只探测 cuda、不加载模型，可安全放在同步工具里。
测试方式 python _mcp_e2e.py：spawn 子进程走真实 stdio JSON-RPC。客户端侧要持续抽干 stderr 管道，否则服务端事件循环会被背压憋住（表现为“调用卡住不超时”）。
接入生效提示：新注册的 MCP 服务器不会自动激活。写入 mcp.json 后，打开 WorkBuddy 连接器管理页 → 自定义连接器 → 对 frameseek 点“信任”，本会话即可通过自然语言调用全部 18 个工具。
